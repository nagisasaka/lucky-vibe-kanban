## 背景
LOCAL-406 の旧 artifact state 検査は schema migration の後、旧予約・復旧記録などの状態を理由にアプリ全体の起動を拒否する。実devでは10/27以前の audit_failed + reserved 3件に該当し、現在の実プロセスやleaseは観測されず、旧版の正式操作でも片付けられないため更新が停止した。初期調査 LOCAL-403。今日のdev復旧とは別作業。

## 方針（確定）
406で追加されたレガシー環境切替の起動時チェックを棚卸しし、専用コードを全削除する。条件緩和・例外リスト・無効化設定・別名の起動ゲート・履歴補正機能に置き換えない。旧レイアウトの互換処理を復活させない。手始めに crates/db/src/models/repository_state/cutover.rs、DB初期化の呼び出し、artifact_layout の参照・専用マーカー、エラー文字列、関連専用テストと現行仕様説明/OpenWikiの全参照を追跡。廃止機構だけが使う実装・型・配線・設定・テスト・説明は削除。同じ関数や構造が現行ランの保護にも必要なら、その用途は削除対象外。適用済みSQLの履歴・checksum、過去のChange Manifestと実ユーザーデータは変更しない。無関係なDB整合、認可、通常の現行プロセスの排他と復旧、正式な再起動手順は変更しない。

## 受入条件
- 削除した実装と参照を列挙。レガシー起動ゲート、代替ゲート、死んだ分岐が残っていないこと。
- 旧予約／旧ファイルを含む合成DBを新バージョンで起動でき、対象履歴やユーザーファイルを変更しない。空DBも起動し、現行の通常の実行・復旧検証が通る。拒否を期待した旧専用テストは削除し、起動を妨げないことの回帰は通常の起動テスト側で確認。
- 実dev DB/既存ファイル操作、実バックアップ削除、マージ、デプロイ、再起動は、このイシューの実装範囲外。今日の先行適用に混ぜない。
