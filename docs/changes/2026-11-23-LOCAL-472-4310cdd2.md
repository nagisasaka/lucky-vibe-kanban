## 結論
カンバンボードの音声をオンにした後、操作や再接続のタイミングで意図せずミュートされる不具合を調べ、再現・修正する。初回の既定オフと、利用者が明示的にオフにする動作は維持。発話停止とボタンがオフへ戻る現象は切り分ける。

## 調査の起点
LOCAL-464 は main/dev に反映済み。main `200a7669` の `packages/web-core/src/features/kanban/ui/RunSpeechToggle.tsx` が `useState(false)` を持ち、アンマウントで観測と発話を止める。単なる再描画ではなく、ヘッダー等の再マウントでオンを失う可能性がある。実際に起こる導線を親 `KanbanContainer` から追い、画面切替、Issue/Workspace の開閉、設定画面、接続失敗・復帰等のうち実際の原因を再現する。発話が一時停止するだけなら polling とブラウザ音声側も区別し、確認できた原因と未確認事項を報告する。

## 受入条件
- 普通の操作・内部再マウント・一時的な再接続で、同じボードを使っている間のオン／オフの選択が変わらない。新しく開くボードは従来どおり既定オフ、プロジェクト間・別タブへ勝手に伝播させない。永続設定や新しいサーバー機構は不要。実装はボード利用中の適切な寿命の層に最小限で置く。明示オフは即時停止・待機クリアを維持する。
- 再接続／再マウント・オンし直しで古いRunの発話を再生したり、別プロジェクトのイベントや重複購読を発生させない。Chrome で可能ならスピーカーの状態と新着イベントの発話を確認。ブラウザで実音を確認できなければ、その点は未確認とする。
- 実際のトリガーを再現する回帰テストと、ユーザーの明示オフが効く確認。必要なら純粋な再マウントと一時通信断もテスト。範囲を絞り、別作業の負荷に配慮。
- LOCAL-469（未マージの音声選択・速度・試聴・読み上げモード）の実装や試聴の挙動を変えない。独立 Workspace で作業し、重なる箇所・統合時の注意を報告。471 や共有 dev/stable、main マージ、公開は触らない。原因・変更・検証を日本語で報告。
