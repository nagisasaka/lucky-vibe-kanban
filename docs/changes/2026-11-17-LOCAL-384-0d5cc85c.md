## 実装フェーズ（2026-11-17）
固定指示の重複配信を実際に減らす。表示だけの変更では完了としない。以下の調査開始時点の制限は初回 REVIEW の履歴であり、この実装には適用しない。

- 同一 native Session の通常継続では、固定指示の全文を重ねて配信しない。Codex は native resume の設定と追加 developer message を区別し、最小案として、前者の固定契約を保ちながら後者は現在値を中心にする。Claude は実測した SessionStart(source=compact) を候補とし、PostCompact が先に来ると仮定しない。
- 初回、新 Session、固定契約が変わった時、根拠のある compaction 後に必要な固定契約を確実に渡す。動的情報は毎 Run 更新する。自動 compact、通常永続 resume、最新値、再送の順序を可能な限り実機で確認。確実に届けられない経路は実装済みと装わず、変更を有効にせず、残条件を報告。設定の信頼付与、権限変更や未承認 hook の実行はしない。
- 実配信に基づく折りたたみ表示も実装する。送信試行と受付を分け、generic success、ACK不明を到達済みと扱わない。指示の権限境界、永続秘密、Manifest、Wiki、通常／専用実行の既存安全境界は維持。
- 通常機能と狭い検証用環境に限る。GitHub push・main マージ・稼働設定変更・再起動はしない。

## 目的
LVK の追加指示を無駄なく渡し、ユーザーが実際の引き渡し内容を確認できるようにする。固定指示と Run ごとの動的情報を分離し、初回・継続・compaction 後の配信と、その事実に基づく折りたたみ表示を一つの Issue で扱う。

2026-11-17 更新：ユーザーの指示で着手する。初手は **REVIEW で両 provider の実機検証まで**。既存製品コード・配信・設定はこの Run では変更しない。下の要件は実装段階の目標として保持する。

- 現 dev の Codex app-server / Claude Code について、実際の CLI バージョン、native Session の起動・継続方法、使える compaction event/hook（前後の違いを含む）を、コードと実挙動で確認する。正式インターフェースを使い、Workspace 内の短いテスト Session / fixture に限定。通常会話や稼働中の 382、ユーザー全体設定、既存セッション、認証情報には触れない。単一 Run 内から正式に片方を試せない場合は必要な別 Session を特定し報告。無理にコストの高い長文で compaction を起こさない。
- 固定文・動的情報には検証用の無害な識別子のみ用い、初回／同一 Session 継続／compaction 後（可能なら新 Session）で、固定指示の到達と回数、現 Run の動的値、表示根拠にできる観測を確認する。実 CLI・fixture・設計上の推論を区別。到達を実証できなければ未確認とし、指示を削らない。
- 最小実装案と、折りたたみ UI に必要な配信記録・重複防止の最小単位を日本語で報告し、実装・マージ・公開は行わず停止する。

## 背景と方針
- LOCAL-347 は LVK から coding agent への指示注入の棚卸し記録。LOCAL-361 はその結果を受けた指示配信の KISS 化、Card Context 等の整理。本件はそれらを再開・上書きせず、そこから見えてきた配信頻度と可視化の改善として分ける。
- 同一の native 会話で固定指示が有効なコンテキストに残っている間は、同じ全文を毎 Run 追記しない方向を目指す。一方で Run ID、現在の identity、Manifest の draft_path などの動的値は最新に保つ。
- ユーザーは「compactation 後には1度だけ再送するのが安全だと思うけどどうだろうか？」と提案した。固定指示は初回と各 compaction 後に一度戻す方針を、両 provider の実挙動を確認して具体化する。
- 「あなた：」の人間の入力はそのまま表示し、その下などに折りたたみ枠を置いて、ユーザー入力以外に引き渡された内容を確認できるようにする。配信方式の差で見えなくしない。

## 要件
### 1. 固定指示と動的情報の配信を分ける
- 現行実装と 347/361 の成果を確認し、LVK 所有の固定契約、Run/Workspace/Repo ごとの動的情報、モード・操作専用指示を整理する。棚卸し全体を無目的にやり直さない。
- 初回、新 Session、同一 Session の継続/resume を区別する。同じ native 会話の通常継続では不要な固定全文の追記を避け、必要な現在値・変更分を届ける。
- 最新 Run ID、Manifest 保存先、現在の対象・実行モードなどを古い値のまま残さない。固定指示が変更された場合も、古い契約を使い続けないための最小の扱いを定める。
- Codex と Claude Code の native な配信方法・ロールの差を尊重し、ユーザー/Repository 由来の内容を不用意に developer 権限へ上げない。

### 2. compaction 後の再送は native 機構を実機で確認してから採用する
- 現在 LVK が利用する Codex / Claude Code の CLI バージョン、起動方式、利用可能な hook/event と追加コンテキストの渡し方を先に確認する。公式仕様にあるだけで現在の LVK で使えるとは扱わない。
- native hook 等を優先し、各 compaction 完了後に必要な固定指示が一度届くことと、その時点の動的値が正しいことを確認する。通知の重複、再接続・再開、失敗時に二重送信や未送信を成功扱いしない。
- 外部監視から別 Run を自動起動する方式、廃止した rollout JSONL/thread 履歴解析や保持判定の復活、独自の巨大な prompt registry・配信管理基盤を前提にしない。
- native 機構が利用不能、または必要な到達を確認できない場合は、その境界と最小の代案を報告する。未検証の保持を根拠に必要な固定契約を削除しない。

### 3. 実際に渡した LVK 追加指示を折りたたみ表示する
- 「あなた：」の入力と LVK の追加指示を明確に分離する。初期状態は折りたたみ、展開すると内容を確認できる。
- Codex の developer instructions、Claude Code の本文への追加、その他の LVK 管理下の引き渡し経路を表示対象にする。実際の経路・ロール、内容、タイミング、対象 Run/Session が分かるようにする。
- その Run で渡した事実に基づいて表示する。固定指示を送っていない継続 Run に毎回送ったような表示をしない。compaction 後の再送は、その発生時点と対象が分かる形にする。
- 過去の内容を現在の設定から再生成して「送信済み」とみなさない。送信失敗・結果不明、古い記録の欠落、参照先の存在と実際の読込を区別する。
- 表示名は「LVK の追加指示」等を候補とし、provider の全 system prompt を網羅していると誤解させない。LVK が渡した／観測できた内容と、CLI が独自に読み込む指示や provider 非公開の内部指示を明確に区別する。観測できないものを推測・抽出しない。

## 維持する境界
- server/provider の permission・scope・guard、権限確認、Review の調査後停止、Manifest・自動 commit、共有資源と parallel の安全境界、通常 Run と自動マージ・Wiki 等の専用契約の分離を維持する。
- 361 で撤去した Card Context・旧 Pipeline・旧 Wiki 等の互換経路を復活させない。保存済みユーザー本文や実データの一括書換え・削除はしない。
- 表示改善のために秘密情報を新たに収集・複製したり、private な別会話や他 Workspace の内容を読み込んだりしない。
- token/費用の削減量は実測がある場合のみ述べ、重複削減をそのまま非キャッシュ課金の削減と断定しない。

## 受入条件
- Codex と Claude Code それぞれについて、実際の CLI バージョンと確認した配信経路を記録する。
- 初回、同一 Session 継続、compaction 後、新 Session の少数の代表例で、固定指示の不要な重複がなく、必要な指示と最新 identity/draft_path が届くことを確認する。
- compaction の重複通知・失敗・再開を変更箇所に絞って検証し、再送の欠落・重複・誤った成功表示を防ぐ。
- UI 上の人間の入力が改変されず、折りたたみ表示の内容・タイミング・経路が実際の LVK 配信記録と一致する。未送信・未観測を隠さない。
- 必要な guard と通常/専用実行の分離が保たれる。実 CLI 検証と fixture/stub を分け、成功・失敗・省略・未確認を日本語で報告する。全モード×全入口の巨大な試験行列は作らない。
