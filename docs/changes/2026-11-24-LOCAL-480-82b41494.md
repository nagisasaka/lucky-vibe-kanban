## 目的

## 調査
1. Codex の承認ポリシーの保存先／読み込み先／優先順を棚卸し。OS ユーザーと Project・repo/worktree・信頼設定・CODEX_HOME、実行プロファイル、入力欄の権限モード、Sandbox Auto、明示 RPC 値を区別。通常 Code/Plan/Review/Goal、新規・再開・継続、UI/remote/stdio の起動入口、Workflow・自動マージ・OpenWiki・保存フィルター推論などを比較。個別 MCP 承認・LVK 独自承認・認可・sandbox を一緒にしない。設定の値・起動時に渡す値・プロバイダーが実際に採用した値を分け、固定の制約はどれが必要か、暗黙既定の最小改善案と互換性を報告。never は操作の全面許可ではない。
2. 通常 Run の入力欄がモデル／推論深さに何を表示するか、実行側との優先順・データ経路を比較。設定ファイル、省略時のプロバイダー既定、プロファイル、明示指定、既存スレッド再開、設定検出失敗・値が存在しないケース、推論深さが非対応のモデルを調べる。「次に使う値」と「実際に使った値」を分ける。「デフォルト」表示の代わりに実名表示を検討し、TOML が空なら設定必須とする案・有効なプロバイダー既定を表示して解決不能時だけ選択させる案を比較。新しい設定機構を安易に増やさない。
