## 調査目的
Run 開始の音声が聞こえた後、カンバンカードが In Progress に移動するまで数秒〜約10秒遅れるという実観測がある。ブラウザが開始を知っている経路とカードの列を決める経路を比較し、どの区間で何を待っているのかを特定する。過去の通信効率化でポーリング間隔を延長した影響は仮説であり、先に結論としない。音声の発話時刻も、サーバー上の真の開始時刻と同一とは仮定しない。

## 調査範囲
- Run の作成・開始、Issue の状態が確定／永続化する時刻、音声開始イベントの配信・ブラウザ到着・実発話、ボード向け差分／スナップショット配信・受信、クエリ無効化または再取得、カードが列に反映されるまでを経路・時刻別に整理する。
- 音声とカードが同じ接続や同じデータを使うか、コード上のポーリング間隔・バックオフ・デバウンス・キャッシュやポーリングへのフォールバックがどこで効くかを確認。別セッション／MCP などボード以外からの起動とボード自身の操作で差があるか、根拠があれば記録する。過去の通信効率化に該当する変更があれば Issue/コミットを示す。
- 既存証跡または隔離した少量の試験で時系列を可能な範囲で計測。測れない区間は推測と区別する。共有 dev・本番データ・進行中の Issue/Run は変更しない。製品コードを修正、コミット、マージ、デプロイしない。

## 報告
結論、遅延区間と測定条件、関連コード・設定、通信削減を損ねずに直す最小案とその検証方法を日本語で報告。原因確定できない場合は不足した証跡を明記する。
