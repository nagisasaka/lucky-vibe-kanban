## 発端と確認済み事項
LOCAL-400 のCodexは、引数なしの `vibe_kanban/get_context` に対して1回限りの承認を要求し、ユーザーが手動で許可した。main反映の承認ではない。
- 稼働版 `da8273ef` の `crates/mcp/src/task_server/tools/context.rs` では、Project・Issue・Workspace等の情報を返すが、ツール宣言に読み取り専用ヒントがない。任意の `guide` 付きの経路も副作用がないことを確認した上で、`tools/list` に `annotations.readOnlyHint: true` が出るようにする。
- 同版の `crates/executors/src/executors/codex.rs` は、自動マージ用のstdio接続で一部ツールに個別承認設定を渡すが、`get_context` は対象外。また、実行プロファイルが承認未指定で標準サンドボックスの場合は起動時に `on-request` を明示する経路がある。
- CodexのMCPツール承認 `Auto` と、実行全体の `approval_policy` は別。Codex公開ソースでは、読み取り専用の印がない場合は `Auto` でも承認が必要になり得る。承認が必要な呼び出しに対する `never` は自動許可ではなく、確認を出さず拒否し得る。LOCAL-400の実効設定値は未確認。検証では使用版を固定する。
