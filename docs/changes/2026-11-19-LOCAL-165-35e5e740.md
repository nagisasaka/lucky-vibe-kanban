## 目的
既存の Lucky Vibe Kanban (LVK) の main リポジトリに Claude Plugin / Marketplace を同梱し、Claude (claude.ai の Web/デスクトップのプラグイン画面を第一対象) から、**LVKのMCP接続と既存 Skillをセットで導入**できるようにする。専用レポジトリは作らず、KISSを優先する。

## 既に合意している設計
1. LVK main に取り込まれた dot 推奨の既存 Skill 配置を尊重する。候補は `skills/lvk-orchestration/SKILL.md`。**最初に main の現物とそのフロントマターを確認し、実際のパスに整合させる**。Skill内容の正本は常に1つとし、Claude用コピーを常設・二重保守しない。
2. LVK本体と同一レポジトリ `nagisasaka/easy-vibe-kanban` 内に Claude Marketplace を追加する。第一候補はルート `.claude-plugin/marketplace.json` による登録、`source: "./"`、既存の Skill ディレクトリを指定する構成。専用の `integrations/claude/skills/` ディレクトリは作らない。
3. 既にユーザーのClaudeには手動でリモートMCP `https://luckyvibekanban.com/mcp` をAuth0 OAuthで正常接続できている。しかし**Pluginテスト前にその既存コネクタはユーザーが手動削除する予定**。したがってPluginをインストールした後、独立した手動コネクタ登録なしで必要なMCP接続・OAuth認証を確立できる構成がゴール。既存の設定やAuth0 client secretをレポジトリにコミットしない。
4. 最小構成を望む。まずMarketplaceエントリの `skills` / `mcpServers` と `strict` による定義で実現できるか検討する。ただし**Claude WebのPlugin管理とClaude Codeでマニフェスト必須性が異なる可能性**があるので、`.claude-plugin/plugin.json`、`.mcp.json` 等が実際に必要なら、公式仕様・根拠を示した上で最小追加する。過去の「JSON 1ファイルだけで十分」は仮説であり、仕様適合が優先。
5. 変更対象は配布設定と必要最小限の導入案内に限定する。LVKサーバー/API、Auth0設定、既存Skillの思想、ChatGPT Pluginは変更しない（明確な互換性問題が見つかった場合は別途判断）。

## 目指す受入条件（実装段階）
- GitHubレポジトリを Claude の Plugins > Add marketplace > Add from repository で登録でき、LVK Pluginをインストールできる。
- Pluginに含まれる既存 `lvk-orchestration` Skillが認識され、内容が正本と一致する。
- 手動登録した既存LVKコネクタを事前削除した状態でも、Pluginを介してLVK MCPのOAuthログイン・Issue一覧取得などが可能。もし現行Claude Webの制約により「PluginだけでMCP導入」は不可能なら、そのことを公式根拠付きで明示して人間に代替案を提示する。安易にSkillだけ成功して全体完成と判定しない。
- Claude Code CLIで可能なら `claude plugin validate .` 相当の妥当性チェックも行う。ただしCLI検証の成功をClaude WebでのOAuth連携成功と混同しない。
- APIキー/Client Secret/tokenを配布物に含めず、ChatGPT側の既存運用に影響を与えない。
