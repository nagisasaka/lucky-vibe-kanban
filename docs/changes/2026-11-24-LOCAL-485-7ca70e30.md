## 結論
自動マージで Git に保存するイシュー本文の控えだけを整形し、セルフホストの接続先や埋め込み先を公開 repo に持ち込まない。LVK 上では人間も上位 AI も従来どおりリンクを使える。新しい設定、専用欄、手作業の確認、Skill の変更は不要。

## 仕様
- Markdown のハイパーリンクは内外問わずリンク先を除き、表示名を残す。参照形式も含み、参照定義のみに URL が残らないようにする。画像は埋め込まず代替テキストだけを残す。意味のあるラベルや本文の Markdown 構造をなるべく維持する。
- 直書きの URL は、既存の `LVK_PUBLIC_URL` と解析済みオリジン（スキーム・ホスト・ポート）が一致するものだけを「LVK 内部リンク」などの URL を含まない文言に置き換える。外部の直書き URL は本文に残す。Markdown の山括弧 URL と自動リンク検出がある場合も、外部の直書き URL を本文から消す仕様にはしない。リンクラベル自体に内部 URL が含まれる場合も残さない。ホストの部分一致やリクエストの Host ヘッダーに頼らない。未設定ならオリジン照合だけ省略する。
- LVK に保存された原文、Wiki その他に渡す本文、過去の Git ファイル、名前・絶対パス・一般本文は変更しない。汎用の秘密検知は対象外。タイトル等の既存メタデータ仕様は変えない。
- LOCAL-484（再マージ対応、未マージ、実装コミット `7726952869ea63432f7821b43b095551090661a7`）と同じ保存経路を触る。今回のコミットに 484 を混ぜず、整形ロジックを分離して差分を小さく保つ。合わせたときは Git に残る整形済み本文で差分判定し、同一 Integration の再試行で結果が変わらないこと。既存の未整形控えとの比較でフィルター導入だけを本文変更と誤認しないよう、同じルールで比較する方針を検討し、組み合わせた結果または統合時に必要な調整を報告する。

## 確認条件
人工の公開オリジンを使い、インライン・参照リンク、画像、内部・外部の直書き URL、同名接頭辞の別ホスト、ポート、設定なし、原文不変、保存済み Git blob を試験する。実データや共有 dev は変更せず、main マージ・デプロイは行わない。日本語で報告する。
