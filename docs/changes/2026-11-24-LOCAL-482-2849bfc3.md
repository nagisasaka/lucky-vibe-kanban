## 目的
カンバンの既存の進捗読み上げ（LOCAL-464/469/475）を改善。ダブルセッション時も耳だけで発話元が分かるようにし、Markdown のバッククオートや強調記号を合成エンジンにそのまま読ませない。LOCAL-480/481 とは別件。

## 確定仕様
### セッション番号と発話
- Workspace 内でセッションの初回開始順に固定の通し番号 1, 2, 3…を割り当てる。現在の同時実行数やタブ順から採番しない。終了済みの番号を再利用せず、同一セッションの次の Run や再開も同じ番号。既存の永続的な順序・ライフサイクル情報を優先し、必要以上の仕組みを足さない。
- 開始通知は、同時セッション数に関係なく番号とエージェント名を読む。例「LOCAL-480 セッション1の作業を Codex が開始しました」「LOCAL-480 セッション2の作業を Claude Code が開始しました」。
- 中間応答は既存の発話対象だけ。稼働が1セッションなら「LOCAL-480：…」、複数なら「LOCAL-480 セッションN：…」。どちらもエージェント名は読まない。Nは固定番号。
- 終了は終わった本人を除いて判定。残りゼロなら「LOCAL-480 の作業を終了しました」、残りがあれば「LOCAL-480 セッションNの作業を終了しました」。成否を誤って成功扱いしない。初回のイベント再生や再接続で複製しない。異なるWorkspaceのRunを残数に混ぜない。Run数ではなく実際に動いているSession数。既存の判定と通知経路を再利用する。
### Markdown
- 読み上げ直前だけ Markdown として解釈し、装飾・マークアップを除いた平文にする。例：太字は本文のみ、インラインコードは囲みを除いて中身を維持、リンクは表示名のみ。語がくっつく箇所は空白補完。C++、インラインコードの a * b、文字どおりの記号などは壊さない。一律置換はしない。
- 画面・ログ・保存済み本文は変更しない。ブラウザ／音声エンジンを問わず共通の読み上げ用整形を使う。既存のオンオフ、キュー、速度、音声選択を維持。

## 検証
単独→2本並行→先行が終了→3本目開始（番号衝突なし）→最後の終了、同じセッションで次Run、同一/異種エージェント、終了前後の競合／再接続／重複、典型的な日本語Markdownとコード・リンク・リテラル記号。既存テストを優先し、ブラウザでは SpeechSynthesis の入力文字列と発話キューを検証。実機のMS/Google音声再生と代替検証を区別して報告。隔離Workspaceで実装と検証、mainマージ・dev/preview反映なし。並行作業があるため不要なRustクリーンビルドや重い試験はしない。
