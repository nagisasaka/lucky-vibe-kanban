## 目的
複数 Workspace を並列実行中、個々の画面を見張らず、別ウィンドウで作業しながら開始・進捗・終了・要対応を聞き流せるようにする。通知音だけでなく、どの Issue に何が起きたかを耳だけで分かるようにする。

## MVP
- カンバンボード右上にスピーカーのオン／オフを置く。設定画面には同じ操作を重複させず、ボードを開いたときは既定オフ。オンのボードのプロジェクト全体が対象で、開いている Workspace だけに限定しない。オン以降の新着だけを読む。オフにしたら再生中の発話と待機分を即時停止し、再度オンにしても読み返さない。
- Run 開始は「LOCAL-463 の作業を開始しました」、成功終了は「LOCAL-463 の作業が完了しました」のような短い定型文。失敗・停止は成功と区別し、回答待ちはユーザーの対応が本当に必要になった遷移だけを知らせる。最終応答本文は読まない。Run を単位とし、Issue 番号を音声に含める。
- 中間は人に向けた agent commentary だけ。Issue 番号を添えて担当の言葉を読む。思考・実行コマンド・ツール入出力・最終応答は対象外。別モデルによる要約、段階の推測、独自の進捗状態は作らない。
- 既存のイベントとボードのブラウザ更新経路を優先して流用し、ブラウザの speechSynthesis で発話。カンバン側で受け取れるイベントを確認し、不足分だけ最小限で補う。再接続・リロード・履歴取得で既出イベントを再生しない。別ウィンドウにフォーカスを移しても、開いた Chrome ボードから聞こえることを実機確認する。

## 同時に来たとき
- ボード側の待ち行列で1件ずつ読み上げる。優先順は「回答待ち・終了」→「開始」→「中間」。同じ優先度では到着順。同じ Run で開始と終端がどちらも未再生なら、古い開始は落として終端だけ読む。
- 中間報告の未再生分は Run ごとに最新1件だけ。終了済み Run の未再生中間報告・回答済みの未再生「回答待ち」は落とす。別 Run から優先イベントが来ても、すでに読んでいる文は割り込まず、次の発話から優先する。明示的なオフだけは即時停止。
- ブラウザ内で制御する。常駐サービス、独自のサーバー側キュー、音声・速度設定や多ブラウザ対応は初回の対象外。

## 受け入れ確認
2つ以上の Workspace の Run を並行実行し、別ウィンドウで作業中に開始・中間・終端・回答待ちが聞き分けられること。発話が重ならず、優先順位・差し替え・古い中間報告の破棄が効くこと。オフで再生とキューが消え、リロード・再接続で過去ログが流れないこと。
