The General tab contains application-wide settings for appearance, default agent, editor configuration, git preferences, and notifications.

## Appearance

Customise how the application looks and feels:

- **Theme** - Choose between Light and Dark colour schemes
- **Language** - Select your preferred language (Browser Default follows your system language)

## Default Coding Agent

<Frame>
<img src="/images/settings-default-coding-agent.png" alt="Default Coding Agent section showing agent and variant dropdowns" />
</Frame>

Set the coding agent that will be used by default when creating new task attempts or follow-ups.

- **Agent** - Select your preferred coding agent (e.g., Claude Code, Gemini CLI, Codex). This determines which AI assistant handles your coding tasks.
- **Variant** - Choose a configuration variant for the selected agent (e.g., Default, Opus, Approvals). Variants contain different settings like planning mode, model selection, or permission levels.

The selected agent and variant appear pre-selected in the attempt creation dialog, saving you time when starting new tasks.

<Tip>
You can override the default agent configuration per attempt in the create attempt dialog. The default is just a convenience for your most common workflow.
</Tip>

## External editor integrations

Register a **menu name** and **URI template** in Settings → General. Add, edit,
remove or reorder entries; the menu follows the saved order. Settings are shared
by everyone using this LVK server. Names must be unique and contain 1–80 characters;
templates may contain up to 8192 UTF-8 bytes.

The initial entry is editable **VS Code** data. Its SSH host is filled once from
the hostname in your browser's LVK address:

```text
vscode://vscode-remote/ssh-remote+your-lvk-host<lvk_workspace_dir>
```

Edit the host if your PC uses a different SSH address or alias. Visiting LVK through
another hostname does not rewrite saved entries. Removing every entry leaves the
list empty, including after a reload.

### URI placeholders

- `<lvk_workspace_dir>`: the absolute Workspace or selected repository directory.
- `<lvk_file_path>`: the absolute target file path, available only in file contexts.

Placeholders work in URI paths and query parameter values. Path expansion preserves
`/` separators; query expansion encodes the whole value. Spaces, Japanese characters
and literal percent signs in paths are encoded. Existing `%XX` escapes in the fixed
part of a template remain escaped; use `%25` for a literal percent sign there.
Placeholders in schemes, authorities, query names or fragments are not supported.
The path placeholder includes its leading slash. For example, use `custom:<lvk_workspace_dir>`
rather than `custom:/<lvk_workspace_dir>`: the extra slash would turn the expanded
path into a URI authority, which LVK rejects.

Examples of editable templates (replace the fixed host or distribution yourself):

```text
vscode://vscode-remote/wsl+Ubuntu<lvk_workspace_dir>
jetbrains://idea/navigate/reference?projectHint=<lvk_workspace_dir>
https://your-web-ide.example/open?path=<lvk_workspace_dir>
```

LVK does not choose an IDE-specific URI format. Consult your application's URI
handler documentation for its current format. HTTP and HTTPS links are supported.

### Open a target

Choose **Open in external editor** from the context or command bar, then select
a named link. Links are prepared before you click; your browser and OS handle the
handoff, permissions and authentication. LVK cannot confirm application launch or
connection success.

A single-repository Workspace opens its worktree. A multi-repository Workspace
opens its root; a repository action opens that repository's worktree. Repository
settings open the registered original repository. File previews also offer the
initial VS Code entry, which opens the directory; add a separate file template
if you want to open the file itself. File-only entries explain why they cannot
be used from a folder context. Missing directories or files produce an error;
resolving a link never restores or creates a worktree.

Previous IDE selections, Custom commands and separate SSH settings are no longer
used. Register a named URI to reconfigure them. LVK does not run editor commands,
install extensions or check IDE availability. The browser and OS decide how to
handle each URI scheme; LVK adds no scheme allowlist or denylist.

Windows application launch, Remote SSH authentication and Dev Containers folder
selection require real-device verification. Nested container URI formats are not
an implemented connection guarantee.

## Git

<Frame>
<img src="/images/settings-git.png" alt="Git settings showing Branch Prefix and Workspace Directory fields" />
</Frame>

Configure git branch naming and workspace storage preferences.

### Branch Prefix

Set a prefix for auto-generated branch names. When you create a new workspace or task, Vibe Kanban automatically creates a git branch for your changes.

| Prefix Setting | Example Branch Name |
|----------------|---------------------|
| `vk` | `vk/1a2b-implement-auth` |
| `feature` | `feature/1a2b-implement-auth` |
| *(empty)* | `1a2b-implement-auth` |

<Tip>
Use a prefix that matches your team's branching conventions (e.g., `feature`, `fix`, or your initials).
</Tip>

### Workspace Directory

Specify where Vibe Kanban stores workspace data. Workspaces are created in a `.vibe-kanban-workspaces` subdirectory within this path.

- **Default location** - Leave empty to use the system default (typically your home directory)
- **Custom location** - Set a specific path if you prefer workspaces on a different drive or directory

<Warning>
Changes to Workspace Directory require an app restart. Existing workspaces remain in their original location.
</Warning>

## Notifications

<Frame>
<img src="/images/settings-notifications.png" alt="Notifications settings showing sound effects and push notifications toggles" />
</Frame>

Configure how Vibe Kanban alerts you about task progress and status changes.

- **Sound Effects** - Play audio notifications when tasks complete, need attention, or encounter errors. Useful when working with multiple tasks or when Vibe Kanban runs in a background tab.
- **Push Notifications** - Receive browser notifications even when Vibe Kanban isn't in focus. Requires browser permission when first enabled.

<Tip>
Enable notifications if you frequently run long-running tasks and want to be alerted when they complete or need your attention.
</Tip>

## Telemetry

Enable or disable telemetry data collection to help improve Vibe Kanban.

## Message Input

Choose the keyboard shortcut to send messages in the chat input (`Enter` or `⌘/Ctrl + Enter`).

<img src="/images/settings-tags.png" alt="Tags section showing task tags table with tag names, content, and actions" />

- **Add Tag +** - Create a new tag
- **Tag Name** - The @mention name for the tag
- **Content** - The text that will be inserted
- **Actions** - Edit or delete existing tags
