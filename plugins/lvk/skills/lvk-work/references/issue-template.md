# Agreed Issue

When creating or materially updating requirements, use whichever headings help
summarize the actual agreement. No fixed template or empty fields are required;
omit inapplicable sections and preserve the user's terminology.

- Purpose, motivation and expected behaviour
- Agreed design decisions and reasons; meaningful deferred alternatives
- Scope and explicit exclusions
- Constraints and compatibility requirements
- Acceptance criteria and relevant verification
- Necessary unresolved decisions

A title alone is not an implementation specification. Do not include unrelated
conversation history or personal preferences. Include a source conversation link
only when the actual link is available; do not invent a ChatGPT URL.

Preserve confirmed intent when updating requirements or sending initial/follow-up instructions, distinguishing agreements, proposals and open points. Do not invent missing reasons or replace them with approval. Issue edits alone do not deliver instructions to an existing coding Session or authorize execution; include changed intent and still-valid constraints in authorized Session follow-ups. Direct conversations with the coding agent carry the same intent into its semantic draft/Change Manifest.
